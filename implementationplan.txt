# AegisOcean — Full System Implementation Plan

## Project Mission

> Detect marine oil spills from Sentinel-1 SAR imagery, characterise the slick geometry,
> hindcast/forecast its drift using oceanographic data, and rank potential polluter vessels
> using historical AIS data — all surfaced through the existing React maritime dashboard.

## Module 1 — SAR Oil Spill Classifier (Two-Stage Training)

**Goal**: Binary classification of SAR chips → Class 0 (no oil) / Class 1 (oil slick)

We use a **curriculum learning strategy**: pretrain a segmentation-capable backbone on the large SOS dataset (pixel-level understanding), then fine-tune the classifier head on the smaller CSIRO chip dataset (task-specific decision boundary).

---

### Dataset A — Deep-SAR SOS (Kaggle) · Pretraining

| Property | Value |
|---|---|
| Source | [Kaggle: bitsandlayers/sar-oil-spill-segmentation-dataset-sos](https://www.kaggle.com/datasets/bitsandlayers/sar-oil-spill-segmentation-dataset-sos) |
| Size | ~1.12 GB |
| Sensors | ALOS PALSAR (Gulf of Mexico) + Sentinel-1A (Persian Gulf) |
| Task | **Semantic segmentation** — image + binary mask pairs |
| Use | Train a U-Net encoder to understand SAR oil spill pixel patterns |

**Why use it first?** Segmentation forces the encoder to learn *spatially-aware* oil/water discriminative features at pixel level — far richer supervision than binary chip labels alone. The encoder then transfers this spatial understanding to chip-level classification.

---

### Dataset B — CSIRO Blondeau-Patissier · Fine-tuning

| Property | Value |
|---|---|
| Source | `data/2022-12-15_.../data/{0,1}/` |
| Size | 5,630 chips (400×400 px, grayscale JPEG) |
| Class 0 | 3,725 chips (66%) — clean sea + look-alikes |
| Class 1 | 1,905 chips (34%) — confirmed oil features |
| Task | **Binary classification** — chip-level label |
| Use | Fine-tune classifier head on task-specific labels |

---

### Two-Stage Architecture

```
╔══════════════════════════════════════════════════════════╗
║  STAGE 1 — Segmentation Pretraining (SOS Dataset)        ║
║                                                          ║
║  EfficientNet-B2 Encoder  +  U-Net Decoder               ║
║  Input: SAR patch + binary mask                          ║
║  Loss: Dice + BCE                                        ║
║  Output: pixel-level oil probability map                 ║
║  → Save encoder weights as `sos_encoder.pt`             ║
╚══════════════════════════════════════════════════════════╝
                          ↓ Transfer encoder weights
╔══════════════════════════════════════════════════════════╗
║  STAGE 2 — Classification Fine-tuning (CSIRO Dataset)    ║
║                                                          ║
║  EfficientNet-B2 Encoder (frozen for 5 epochs)           ║
║  + Global Average Pooling                                ║
║  + Dropout(0.3) → Dense(256, ReLU) → Dropout(0.2)        ║
║  + Dense(1, Sigmoid)                                     ║
║  Loss: Focal Loss (γ=2) + pos_weight=1.96                ║
║  Output: P(oil | chip)                                   ║
╚══════════════════════════════════════════════════════════╝
```

---

### Stage 1 — Segmentation Pretraining Config

| Param | Value |
|---|---|
| Architecture | U-Net with EfficientNet-B2 encoder (via `segmentation-models-pytorch`) |
| Input channels | 1 (grayscale SAR) |
| Input size | 512×512 (PALSAR) / 256×256 (Sentinel patches) |
| Loss | 0.5 × DiceLoss + 0.5 × BCEWithLogitsLoss |
| Optimizer | AdamW (lr=2e-4, wd=1e-4) |
| Scheduler | CosineAnnealingLR (T_max=30) |
| Epochs | 40, early stop on val IoU (patience=8) |
| Batch size | 16 |
| Augmentation | H/V flip, elastic deform, Gaussian noise, brightness/contrast |
| Target | Val IoU ≥ 0.70, val Dice ≥ 0.75 |

### Stage 2 — Classification Fine-tuning Config

| Param | Value |
|---|---|
| Encoder init | `sos_encoder.pt` (Stage 1 weights) |
| Encoder frozen | First 5 epochs (warm-up classifier head only) |
| Full fine-tune | Epochs 6–50 with lr=1e-4 |
| Input size | 400×400 → 224×224 |
| Loss | Focal Loss (γ=2) + pos_weight=1.96 |
| Optimizer | AdamW (lr=1e-4 → 1e-5 for encoder) |
| Scheduler | CosineAnnealingWarmRestarts (T_0=10) |
| Epochs | 50, early stop on val F1-class1 (patience=10) |
| Sampler | `WeightedRandomSampler` (2:1 class correction) |
| Primary metric | **F1-score (Class 1 — oil)** |
| Target | Val F1 ≥ 0.87, AUC-ROC ≥ 0.92 |

> [!TIP]
> Using the SOS-pretrained encoder is expected to give **+4–8% F1** over ImageNet-only pretraining, because the encoder already understands SAR texture, speckle, and oil signatures before seeing a single CSIRO chip.

---

### Data Pipelines

**Stage 1 — SOS Dataset**
```
SOS patches (SAR image + binary mask)
  → Resize to 512×512 (PALSAR) or 256×256 (Sentinel)
  → Normalize to [0,1] using per-sensor statistics
  → Augment: flip, rotate, elastic, noise
  → Stack patches into batches
  → U-Net → pixel-wise sigmoid → Dice+BCE loss
```

**Stage 2 — CSIRO Dataset**
```
CSIRO chips (400×400 grayscale JPEG)
  → Stratified split 70/15/15, seed=42
  → Resize to 224×224
  → Normalize: mean=0.449, std=0.226 (SAR grayscale)
  → Augment: H/V flip, rotation ±15°, Gaussian noise σ=0.01
  → WeightedRandomSampler (oversample class 1 by 1.96×)
  → EfficientNet-B2 classifier → Focal loss
```

## Module 2 — Slick Characterisation Engine

**Goal**: From a classified chip (or full SAR scene), extract geometric/physical properties of the slick and estimate spill age.

### Geometric Properties (from chip bounding polygon)

| Property | Method |
|---|---|
| Area (km²) | Haversine polygon area from GeoJSON coordinates |
| Perimeter (km) | Haversine segment sum |
| Perimeter-to-Area ratio | Discriminates oil (low) from wind/biogenic look-alikes (high) |
| Centroid (lon/lat) | Polygon centroid → origin estimate for drift |
| Elongation / compactness | Ellipse fit → indicates drift direction |
| Thickness estimate | Radar backscatter value → Bonn Agreement color code |

### Slick Age Estimation

Using the empirical formula from Fingas & Brown (2018):
- Oil spreads at ~1–3 km²/hr under calm conditions
- Corrected by wind speed: `age_hours = area_km2 / (0.8 × wind_speed_ms)`
- Returns `estimatedAgeHours` with confidence interval

### Look-alike Confidence Score

```
windArtifactConfidence = f(perimeterToAreaRatio, elongation, backscatter_std)
```

> Already present in `incidents.json` schema — will be populated by this engine.

### Files

```
backend/
└── characterise.py   # GeometryAnalyser class: area, perimeter, age, look-alike score
```

## Module 3 — Oceanographic Drift Model

**Goal**: Given detected slick centroid + detection timestamp, **hindcast** the slick origin (backward) and **forecast** future spread (forward) using ocean currents + wind.

### Data Sources — ✅ Both Confirmed

| Source | Data | Credentials |
|---|---|---|
| **CMEMS** (Copernicus Marine) | Sea surface currents (u/v, 1/12° grid), SST | ✅ Account confirmed — `copernicusmarine` Python SDK |
| **ERA5** (ECMWF) | 10m wind vectors (u10, v10, hourly) | CDS API (`~/.cdsapirc` key file) |

### CMEMS Product Used

```
Dataset: cmems_mod_glo_phy_anfc_0.083deg_PT1H-m
Variables: uo (eastward current), vo (northward current)
Bounding box: lon=[60, 100], lat=[5, 25]  ← Indian EEZ
Depth: surface (0m)
Resolution: 1/12° (~9km) spatial, 1h temporal
Access: copernicusmarine.open_dataset(...)
```

### Simulation Design (OpenDrift)

```
Detected slick centroid (lon, lat, t=0) — Indian EEZ
          ↓
Release N=500 virtual particles at centroid
          ↓
Run BACKWARD in time: t=0 → t=-72h (hindcast)
  Using: CMEMS currents (reversed) + ERA5 wind drift (3% rule, reversed)
  → Probability heatmap: P(origin | particle position) at each −24h step
          ↓
Run FORWARD in time: t=0 → t=+48h (forecast)
  Standard forward Lagrangian drift with weathering model
  → Future slick extent as expanding polygon
          ↓
Output: drift.json per incident (matches existing mock schema exactly)
```

### Output Schema (matches existing `drift.json`)

```json
{
  "timestampOffsetHours": -48,
  "originHeatmap": {
    "type": "FeatureCollection",
    "features": [
      {"geometry": {"type": "Point", "coordinates": [lon, lat]},
       "properties": {"weight": 0.85}}
    ]
  }
}
```

├── data_fetchers/
│   ├── cmems.py      # copernicusmarine SDK client — Indian EEZ bbox

## Module 4 — AIS Vessel Attribution Engine

**Goal**: Given the hindcast origin window (region + time range), query **MarineTraffic** for historical vessel positions within the Indian EEZ, filter irrelevant traffic, and score suspect vessels.

### AIS Data Source — MarineTraffic API ✅ Confirmed

| Property | Detail |
|---|---|
| Provider | [MarineTraffic](https://www.marinetraffic.com/en/ais-api-services) |
| Endpoints used | `getVesselsInArea` (real-time), `getVesselTrackExtended` (historical AIS replay) |
| Auth | API key in `backend/.env` — never committed to git |
| Rate limit | Depends on plan tier — responses cached to SQLite to minimize API calls |
| Coverage area | **Indian EEZ bounding box**: lon 60°E–100°E, lat 5°N–25°N |
| History depth | Up to 30 days historical track replay per vessel |

### MarineTraffic Query Flow

```
Hindcast origin window (lon, lat, radius_km, t_start, t_end)
          ↓
1. getVesselsInArea(bbox, time_range)
   → returns: MMSI, vessel_name, vessel_type, last_position, COG, SOG
          ↓
2. For each vessel in area: getVesselTrackExtended(MMSI, from, to)
   → returns: timestamped position array → reconstruct full track
          ↓
3. Dark vessel detection: gaps > 2h in AIS track → flag as non-transponding
          ↓
4. Score + rank (see below)
```

### Suspect Scoring Algorithm

```python
suspectScore = weighted_sum(
    proximity_score     × 0.30,   # closest approach to estimated origin (km)
    temporal_score      × 0.25,   # time of transit vs estimated spill time
    vessel_risk_weight  × 0.20,   # tanker(1.0) > bulk(0.7) > container(0.5) > other(0.3)
    anomaly_index       × 0.15,   # AIS gap duration, speed drops, course deviation
    dark_vessel_flag    × 0.10,   # +0.3 bonus if MMSI missing or AIS gap > 2h at site
)
```

### Scoring Detail

| Component | Calculation |
|---|---|
| `proximity_score` | `exp(-minDistKm / 10)` — exponential decay, 0.5 at 7km |
| `temporal_score` | `1 - abs(transitDelta_h) / 24` — peaks at transit = spill time |
| `vessel_risk_weight` | Lookup table by AIS ship type code |
| `anomaly_index` | Normalised: AIS gap hrs + |ΔSoG| + heading deviation / max_possible |
| `dark_vessel_flag` | 1 if MMSI=null OR AIS gap >2h within 20km of origin, else 0 |

### Filtering Logic

1. **Spatial**: vessels within 50 km of hindcast origin centroid
2. **Temporal**: vessels present ±24h around estimated spill time
3. **Type exclusion**: coast guard, naval, SAR vessels (excluded unless anomalous)
4. **Indian EEZ clipping**: all tracks clipped to EEZ polygon before scoring
5. **Rank** by `suspectScore` DESC → top-5 returned to `SuspectPanel`

### AIS Cache Strategy

- SQLite database `backend/cache/ais_cache.db` — stores raw API responses keyed by `(MMSI, date)`
- TTL: 7 days for historical tracks (immutable), 5 min for real-time positions
- Prevents re-querying same vessel during iterative development

## Module 5 — FastAPI Backend

**Goal**: Replace the mock `apiClient` in the React frontend with a real Python backend that routes requests to ML/physics modules.

### API Contract (matches existing `apiClient.ts` calls)

| Endpoint | Method | Returns |
|---|---|---|
| `GET /api/incidents` | GET | List of incident objects with polygon + properties |
| `GET /api/incidents/{id}` | GET | Single incident details |
| `GET /api/incidents/{id}/drift` | GET | Array of drift frames (heatmap per timestep) |
| `GET /api/incidents/{id}/suspects` | GET | Ranked list of vessel suspects with score |
| `POST /api/analyze` | POST | Trigger full analysis pipeline on new SAR chip |

### Pipeline on `POST /api/analyze`

```
1. Run SAR classifier → confidence score
2. If confidence > 0.6 → characterise geometry
3. Fetch CMEMS + ERA5 data for detected location/time
4. Run OpenDrift hindcast + forecast (async, ~2min)
5. Fetch + score AIS vessels in origin window
6. Persist incident record → return incident ID
```

## Resolved Decisions

> [!NOTE]
> **AIS Data** ✅ **MarineTraffic API** — `getVesselsInArea` for real-time scan + `getVesselTrackExtended` for historical replay. API key stored in `backend/.env`. SQLite cache layer to manage rate limits.

> [!NOTE]
> **CMEMS** ✅ **Account confirmed** — Using `copernicusmarine` Python SDK. Product: `cmems_mod_glo_phy_anfc_0.083deg_PT1H-m` (hourly surface currents). Bounding box locked to Indian EEZ: lon 60–100°E, lat 5–25°N.

> [!NOTE]
> **Deployment** ✅ **Local macOS** — Training uses Apple MPS (`device = torch.device("mps")`) if GPU detected, falls back to CPU. FastAPI runs via `uvicorn` on `localhost:8000`. React dev server on `localhost:5173`.

> [!NOTE]
> **Augmented chips** ✅ **Independent samples** — Pre-augmented chips (`slant`, `rotate`, `crop` suffix) are treated as separate training examples. No deduplication. This increases effective dataset diversity.

> [!NOTE]
> **Region scope** ✅ **Indian EEZ** — All spatial filters, API bounding boxes, and EEZ polygon clipping target the Indian Exclusive Economic Zone (lon 60–100°E, lat 5–25°N). The frontend already displays the India EEZ boundary and Indian port markers.
